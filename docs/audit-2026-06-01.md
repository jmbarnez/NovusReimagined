# 2026-06-01 — Canvas 2D → PixiJS audit

This audit captures the state of the codebase after the seven-PR migration that
removed the second `<canvas>` surface and unified all in-game rendering on
PixiJS. The companion `docs/audit-2026-05-31.md` (and earlier `AUDIT.md`)
remain in place as the historical record of the prior state.

## Background

The game has, for most of its life, been a dual-renderer:

1. A PixiJS application that owns the world, the UI overlays, and most of the
   combat/ship visuals.
2. A screen-space `<canvas id="c">` (`src/canvas.ts`) that drew HUD overlays,
   the map panels, the warp screen, the station interior, the tutorial dimmer
   cutouts, the system map radar sweep, and the legacy galaxy map.

The two surfaces were stacked (Pixi at `zIndex 0`, screen canvas at `zIndex 1`)
and synchronized per frame by the game loop. Maintaining the screen canvas
required a parallel `ctx` to every Pixi renderer, plus a per-frame
`ctx.clearRect()` so that Pixi would show through.

## Goals

- **Single renderer.** All in-game rendering happens inside PixiJS.
- **No `<canvas id="c">` element in `index.html`.**
- **No `src/canvas.ts` module.** Its `W`/`H`/`ctx`/`canvasLeft`/`canvasTop`
  helpers are replaced by `viewportW`/`viewportH`/`viewportLeft`/`viewportTop`
  in `src/render/viewport.ts`.
- **No `getElementById("c")` lookups.** Any DOM that used the screen canvas for
  cursor styling now targets the Pixi canvas (`app.canvas`).
- **Guardrail test.** `tests/canvas-2d-ban.test.ts` greps the entire `src/`
  tree and fails the build if anyone re-imports from `canvas.js` or re-creates
  `src/canvas.ts`.
- **AGENTS.md rule.** Operating Principle #2 lists Pixi-only rendering so the
  intent is documented next to the rest of the agent's working rules.

## PR sequence

### PR 1 — Map window backdrop blur
- `src/ui/styles/bridge.css` — `#hud-win-map` and its header/body override
  `backdrop-filter: none`.
- `src/ui/styles/map-overlay.css` — `#hud-win-body-map` is set to
  `background: transparent` so the map content renders against the play
  surface instead of a frosted panel.
- The other bridge windows (`#hud-win-*`) keep the original
  `backdrop-filter: blur(...)` look.

### PR 2 — Delete dead Canvas 2D code
- Removed `src/render/world.ts`, `src/render/world-overlays.ts`, and the entire
  `src/render/world/` subdirectory (7 files, ~1,800 LOC of unused Canvas 2D
  ship/asteroid/enemy/wreck/environment renderers).
- Cleaned up `src/render/world-label-card.ts` and `src/render/world-text.ts`
  to keep only the world-to-screen helpers that the labels still use.
- Inlined a minimal `shipPath(shipId)` helper in `src/render/station-interior.ts`
  to unblock the build; deleted entirely in PR 5c.

### PR 3 — W/H/resize/dispose migration
- `src/render/viewport.ts` now owns `setViewportSize`, `viewportW`,
  `viewportH`, and a shared `playRect`.
- `src/pixi.ts` consumes the shared `playRect` and calls `setViewportSize`
  on init and resize, so the Pixi renderer's dimensions stay in sync with
  the rest of the world.
- New `src/render/pixi-chat-bubbles.ts` uses the shared viewport helpers
  (replaces a small inline Canvas 2D chat bubble pass).
- `src/render/pixi-background.ts`, `src/render/pixi-effects-overlay.ts`, and
  `src/render/pixi-nebula-gpu.ts` no longer import `W`/`H` from `canvas.js`.
- `src/ui/settings/listeners.ts` and `src/ui/settings/reset.ts` no longer
  import the `resize` symbol.
- `src/game-loop/runtime.ts` no longer calls `disposeCanvas()`.

### PR 4 — Off-screen bakers
- `src/render/background.ts` — removed `drawBackground` and the per-frame
  starfield canvas painter; left only `initBackgroundStars` (which bakes a
  single Pixi `Texture` from an `OffscreenCanvas` once at startup).
- `src/render/seeded-detail.ts` — removed `rimLightStroke` (dead code).
- `src/render/world-label-card.ts` — removed `drawWorldLabelCard` (dead code).
- `src/render/world-text.ts` — removed `worldText`/`worldCardText` (dead
  code); kept `setWorldView` and `worldToScreen` which are still used by the
  world-space label layout code.

### PR 5 — Migrate the visible Canvas 2D renderers

**5a — Map survey overlays.** `drawPassiveRadarOverlay` and
`drawMapSurveyOverlay` in `src/ui/map-survey.ts` now take a `Graphics`
parameter and use `arc`, `stroke`, `fill` instead of `ctx`. The radial
gradients (which Pixi v8 does not expose on `Graphics`) are approximated with
a layered alpha fill.

**5b — Warp screen.** New `src/render/pixi-warp-screen.ts` exports
`syncPixiWarpScreen(now)`. The hyperspace streaks, central bloom, vignette,
arrival flash, and text overlays are all `Graphics` + `Text` primitives
attached to `screenContainer`. `src/render/hud/warp-screen.ts` is deleted;
`src/game-loop/render-pass.ts` calls the new sync function.

**5c — Station interior.** New `src/render/pixi-station-interior.ts` exports
`syncPixiStationInterior(now)`. The hangar scene (floor perspective grid,
side walls, viewport, docking platform, ship silhouette, hologram rings,
dust, welding sparks) is drawn into a `Container` that lives on
`screenContainer`. The static layer is rebaked on viewport resize; the
animated parts redraw every frame. `src/render/station-interior.ts` and the
temporary `shipPath` helper are deleted.

**5d — HUD minimap.** `src/render/hud/maps.ts` and `src/render/hud.ts` were
discovered to be dead code: `drawGalaxyMap` and `drawSystemMap` were never
called from anywhere (`syncPixiSystemMap` in `src/render/pixi-maps.ts` is the
real renderer). Both files were deleted.

**5e — Tutorial overlay.** `src/ui/tutorial-overlay.ts` is DOM-based; the
only canvas interaction was `W`/`H`/`canvasLeft`/`canvasTop` for sizing the
overlay layer. Those imports were swapped for the new viewport helpers.

After PR 5, `src/render/pixi-maps.ts` no longer imports `ctx`: the
`drawPixiSystemMapCanvasOverlays` function now drives the dynamic overlays
(passive radar, survey cone, tutorial tracks) through a single
`overlayGfx: Graphics` in the Pixi map container.

### PR 6 — Delete the screen canvas
- `src/canvas.ts` removed entirely.
- `<canvas id="c">` and the `#c` CSS rule removed from `index.html`.
- `src/game-loop/render-pass.ts` no longer calls `ctx.clearRect` on the
  front canvas; the dead `drawDamageFlash` and `drawWaypoint` helpers were
  removed.
- `src/input.ts` and `src/dock.ts` now target the Pixi canvas via
  `app.canvas` for cursor styling.
- `src/utils/mining.ts` lost `drawAsteroidDebris` (dead code; the visual
  layer is drawn by `src/render/pixi-effects.ts`).

### PR 7 — Guardrail and documentation
- `tests/canvas-2d-ban.test.ts` greps `src/**` for `from "…canvas.js"` and
  asserts `src/canvas.ts` does not exist. The test fails the suite if either
  invariant is violated.
- `AGENTS.md` Operating Principle #2 documents the Pixi-only rule and
  points new contributors at the guard test.
- This audit file lives at `docs/audit-2026-06-01.md`.

## Behavioural notes

- **Gradient fidelity.** The old Canvas 2D renderers used
  `createLinearGradient` and `createRadialGradient` heavily. Pixi v8's
  `Graphics` does not support live gradients, so the new renderers either
  bake a one-time `OffscreenCanvas` to a `Texture` (background) or fall
  back to flat colour + alpha overlays (warp screen bloom, station
  interior side walls). The visual difference is small and the cost is
  significantly lower.
- **Cursor styling.** Before PR 6 the cursor was set on the screen canvas
  (`#c`). It is now set on the Pixi canvas. The body cursor is not
  affected, so HUD elements keep their own cursor styles via CSS.
- **Map window transparency.** The map window no longer draws a frosted
  panel; the system map background (`#hud-win-body-map { background: transparent }`)
  blends with the world underneath.

## Open follow-ups (not in scope for this audit)

- The map survey's two static radial gradient approximations could be
  replaced with a single baked texture if a visible quality gap is
  reported.
- The `system-lock-resolution` test is timing-flaky; consider raising
  the timeout or refactoring to use `vi.useFakeTimers`.
- `pixi-station-interior.ts` redraws the static layer on resize only;
  if the viewport changes during a docking transition the rebake will
  happen mid-frame and may flicker for one tick. In practice the
  viewport doesn't change while docked.
