# Controls cleanup & onboarding

## Context

The control scheme is EVE-style indirect flight: **right-click to set a waypoint / open an enemy menu**, **left-click to lock**, **1–0 to activate modules / assign turrets**, **Space to brake**, mouse aims the hull. That's coherent for the genre, but a code audit turned up three things the code *promises* but doesn't *deliver* — they read as bugs to a new player:

1. **Dead WASD.** `up/down/left/right` exist in [`Keybinds`](src/data/settings.ts#L11-L14), [`DEFAULT_KEYBINDS`](src/data/settings.ts#L98-L101) and [`KEYBIND_LABELS`](src/data/settings.ts#L113-L116) ("Thrust Forward/…"), are rebindable in the settings UI, but **nothing reads them** — `Client.keys` is only ever consulted for the brake/space key ([ship.ts:118](src/physics/ship.ts#L118)). Pressing W does nothing while the settings screen claims it thrusts.
2. **Dead manual-fire path.** `Client.mouse.firing` gates an auto-fire-on-LMB block ([combat.ts:106-108](src/combat.ts#L106-L108)) but is **never set to `true`** anywhere — only to `false` ([input.ts:140](src/input.ts#L140), [input.ts:194](src/input.ts#L194)). Firing actually happens via turret-to-target assignment. The leftover field/branch is misleading dead code.
3. **No onboarding.** With no waypoint set the ship just rotates toward the cursor without moving, and nothing tells a new player "right-click to move." The always-on `#hud-help` side panel ([hud-overlay.ts:74-92](src/ui/hud-overlay.ts#L74-L92)) is correct but too faint/easy to miss in the first seconds.

Decision (per user): commit fully to click-to-move — **remove** the misleading WASD bindings rather than wire them up, **clean** the dead fire path, and **add** a first-run hint.

## Changes

### 1. Remove dead WASD bindings
In [src/data/settings.ts](src/data/settings.ts):
- Drop `up`, `down`, `left`, `right` from the `Keybinds` interface ([L11-L14](src/data/settings.ts#L11-L14)).
- Drop the same four entries from `DEFAULT_KEYBINDS` ([L98-L101](src/data/settings.ts#L98-L101)) and `KEYBIND_LABELS` ([L113-L116](src/data/settings.ts#L113-L116)).

The settings rebind list is generated by iterating `KEYBIND_LABELS` ([settings.ts:435](src/ui/settings.ts#L435)), so the four rows disappear automatically — no UI edit needed. `loadSettings()` spreads `DEFAULT_KEYBINDS` first ([settings.ts:379](src/data/settings.ts#L379)), so any WASD keys already saved in a player's `localStorage` are harmlessly ignored. Grep confirmed **zero** other consumers of `keybinds.up/down/left/right`.

### 2. Clean the dead fire path
- [src/state.ts](src/state.ts): remove `firing` from the `mouse` type ([L163](src/state.ts#L163)) and its initializer ([L215](src/state.ts#L215)).
- [src/input.ts](src/input.ts): remove the two `Client.mouse.firing = false` lines ([L140](src/input.ts#L140), [L194](src/input.ts#L194)). (The `blur` and LMB-up handlers still reset `lmb`.)
- [src/combat.ts](src/combat.ts): remove the `if (Client.mouse.firing) { fireSelectedTurret(true); }` block ([L106-L108](src/combat.ts#L106-L108)). Since `firing` is never `true`, this is a behavior-preserving deletion. Leave `fireSelectedTurret` itself (still used by hotkeys).

### 3. First-run onboarding hint
A transient, dismissible banner shown once per browser, surfacing the three non-obvious core controls.
- **Markup**: add a `<div id="hud-onboard">` to the `overlay.innerHTML` in [hud-overlay.ts:41-93](src/ui/hud-overlay.ts#L41-L93), with three lines: `Right-click to move` · `Left-click to lock a target` · `1–0 to fire / activate modules`. Render it only when `localStorage.getItem("novus-onboarded")` is absent (mirror the `SETTINGS_KEY` localStorage pattern in [settings.ts](src/data/settings.ts#L1)).
- **Dismissal**: hide + set the localStorage flag the first time the player actually moves (`Client.waypoint` becomes non-null) or after a ~12s timeout. Simplest hook: a small check in the existing HUD update path, or a one-shot listener added in `initHudOverlay`. Auto-fade via a CSS class.
- **Style**: add `#hud-onboard` rules to [src/ui/styles/hud-misc.css](src/ui/styles/hud-misc.css) next to the existing `#hud-help` block ([L17-L55](src/ui/styles/hud-misc.css#L17-L55)) — centered near top, `pointer-events: none`, opacity transition for the fade-out. Reuse the theme vars (`--hud-border-soft`, `--hud-text-*`) already used there.

### 4. Keep `#hud-help` honest
The persistent help panel already omits WASD and matches the real scheme — no change required, but verify it still reads correctly after the above (it does: "RMB Set Waypoint / Mouse Aim / LMB Lock / 1-0 Activate").

## Verification
- `npx tsc --noEmit` (or the project's typecheck) — confirms removing the `Keybinds` fields and `mouse.firing` breaks no references.
- Run the app (`/run`): 
  - Open **Settings → keybinds**: the four Thrust rows are gone; remaining binds (Inventory, Overview, Map, Dock, Brake, Skills, Settings, Perf) still rebind correctly.
  - **New session** (clear `localStorage` or use a fresh profile): the onboarding hint appears on game start, then disappears after the first right-click move and stays gone on reload.
  - **Combat unchanged**: lock a target (LMB), assign a turret (number key / shift-click), confirm it auto-fires — i.e. removing the `firing` block changed nothing.
  - Press W/A/S/D in flight: confirm they were already inert (no regression).
