# src/ Codebase Audit — May 31, 2026

**Scope:** `src/` only (~15k+ lines across 143 TS files + CSS)
**Method:** Architectural boundary scan, TODO/legacy sweep, type-safety review, perf hot-path audit, i18n check

---

## Executive Summary

The codebase is well-organized and most previous debt has been paid down. This audit surfaces **3 critical issues**, **7 high-severity items**, and a scattering of medium/low cleanup. The biggest surprise is that `src/render/world/` — documented as "fully deleted" — is still alive and on the main render path.

---

## Critical

### 1. Direct `getState().player = ...` mutations outside `PlayerAccess`
- **`src/data/profiles.ts:100`** — `getState().player = player;`
- **`src/ui/boot-screen/boot-screen-profiles.ts:195`** — `getState().player = freshPlayer;`
- **`src/ui/boot-screen/boot-screen-profiles.ts:199`** — `getState().player.sysIdx = 0;`

These violate `AGENTS.md` rule: *"All `G.*` and `G.P.*` field writes must go through accessors in `src/state-access.ts`"*. They bypass the entire encapsulation layer. Fix: add `PlayerAccess.installPlayer()` / `PlayerAccess.setSysIdx()` and route through those methods.

### 2. `src/render/world/` falsely documented as "fully deleted"
`docs/architecture.md` Resolved Debt claims: *"fully deleting the `render/world/` sub-directory"*. The directory **still exists** with 7 files (~65 KB) and is imported by the main render loop:

```
src/game-loop/render-pass.ts:7  → import { drawStations, drawStationTurrets, drawCrosshair, drawLensFlare } from "../render/world.js";
src/render/world.ts             → barrel re-export of render/world/*.ts
```

Active files:
- `render/world/celestial.ts` (11.7 KB)
- `render/world/combat.ts` (12.3 KB)
- `render/world/effects.ts` (6.1 KB)
- `render/world/entities.ts` (16.0 KB)
- `render/world/environment.ts` (1.1 KB)
- `render/world/structures.ts` (6.7 KB)
- `render/world/wrecks-pickups.ts` (15.4 KB)

These are Canvas 2D overlays that run **every frame** alongside PixiJS. Either the docs are wrong (the directory was recreated or never deleted) or the debt item was prematurely checked off. **Impact:** duplicated rendering effort, misleading architecture docs.

### 3. Bug: duplicate `name.className` assignment in slot rebuild
**`src/ui/hud/slots.ts:147`** — ✅ **Fixed**

Line 147 redundantly overwrote `name.className` (already set on line 142). The redundant line has been removed.

## High

### 4. `JSON.parse(raw) as Player` — unsafe deserialization without validation
- **`src/player/player-data.ts:160`** — `const p = JSON.parse(raw) as Player;`
- **`src/data/profiles.ts:188`** — `const player = JSON.parse(raw) as Player;`

AGENTS.md type-safety rules say: *"Use `unknown` for unsafe boundaries [...] Narrow types with guards"*. Both sites cast straight to `Player` instead of `unknown` → validation → narrowing. `player-data.ts` does defensive patching afterward, but a malicious/corrupted save could still hit runtime errors before the patch phase. Fix: parse as `unknown`, run a `isPlayerLike` predicate, then narrow.

### 5. Type assertions bypassing the type system
- **`src/player/player-stats.ts:264`** — `(m as { salvageRollBonus?: number }).salvageRollBonus`
- **`src/player/player-stats.ts:333`** — `(m as { isComms?: boolean }).isComms`

These properties should be declared on `ModuleDef` (or a subtype) rather than cast at every use site. The `isComms` flag in particular is checked in a hot loop during stats computation.

### 6. Hardcoded English strings in `logEvent` / `floatText` / `confirm`
The i18n system (`src/utils/i18n.ts`) is well-built, but many simulation and UI paths still hardcode English:

- **`src/player/player-data.ts:296,298,322,324,328`** — level-up / skill-up floatText and logEvent strings
- **`src/data/missions.ts:163,189`** — `Contract complete: ${c.title} — dock to claim ${c.reward} CR`
- **`src/ui/boot-screen/boot-screen-profiles.ts:81`** — `confirm(t("profile.confirmDelete", { name: pilotName }))` (wrapped, but many other `confirm`/`alert` calls across 17 files use raw strings)
- **`src/combat.ts`**, **`src/tutorial.ts`**, **`src/hub.ts`**, **`src/player/player-fitting.ts`** — 91 total hardcoded string matches in `logEvent`/`floatText` calls

### 7. Per-frame force reflow in `flashSlotFire`
**`src/ui/hud/slots.ts:452`**
```ts
void node.el.offsetWidth; // force reflow to restart animation
```

Called every time a slot fires. Forces synchronous layout. If multiple slots fire on the same frame, this becomes a layout thrashing hotspot. Consider CSS animation keyframe restart via className swap without offsetWidth read.

### 8. `render/world/` per-frame Canvas 2D gradient allocations
**`src/render/world/combat.ts:22`** and other files create `ctx.createRadialGradient` on some code paths each frame. The previous audit noted ~85 gradient calls/frame; many are still in the "deleted" `render/world/` files. `_salvageSparkCache` in `combat.ts` is cached, but other gradients (mining laser, gate glows, station rings) are not.

### 9. `innerHTML` assignments without compare-before-write in settings render
**`src/ui/settings/render.ts:68-74, 89-95, 109-111, 128-133, 157-166`**

Re-renders entire DOM trees on every settings change. While the HTML is self-generated (not user input), this is heavier than necessary and was flagged in the previous audit as a to-do item that remains open.

### 10. `new Set<string>()` in scanning module
**`src/scanning.ts:20`** — ✅ **Fixed**

Module-scoped Set that was never cleared, causing unbounded memory growth if the player surveys many unique sites. Fixed by capping at 500 entries with LRU eviction (oldest entry removed when limit reached).
